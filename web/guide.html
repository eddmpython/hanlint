내 글은 어디에 남나요?

검사와 수정 비교는 브라우저에서 실행합니다. 글을 붙여 넣는 것만으로 원고를 외부에 보내지 않습니다. 사이트 파일을 받는 요청과 사용자가 선택한 외부 링크 방문은 별개입니다.

글을 넣고 고치기

예문을 전체 선택해 내 글을 붙여 넣거나 파일을 열면, 그 글이 수정 전 원문이 됩니다. 기존 원고는 수정 이력에 남습니다. 빈 편집기에 직접 쓰는 글은 고치기 전에 ‘수정본 기록’으로 원문을 남겨 주세요. 자동 고침은 고치기 전 원문을 먼저 보관합니다.

브라우저의 개인 기록

편집 중인 원고는 브라우저에 임시 보관합니다. ‘수정본 기록’을 누르면 그 시점의 원고와 수정 전 원문, 글 종류, 엔진 버전, 선택한 수정 이유와 수정 방식을 남깁니다. 브라우저 데이터 삭제나 비공개 창 종료로 기록이 사라질 수 있으니, ‘내 기록’에서 내보내거나 GitHub에 보관해 주세요.

원고는 60,000자, 기록은 100개까지 다룹니다. 기록 파일은 900 KB까지 가져오고 저장할 수 있습니다. 제한에 닿으면 이전 기록을 내보내고 정리해 주세요. 보관 한도를 넘었다고 오래된 글을 자동으로 삭제하지 않습니다.

내 GitHub에 저장하기

  1. 개인 GitHub 저장소를 하나 만듭니다. 원고를 공개하지 않으려면 비공개로 만드세요.
  2. Fine-grained personal access token을 만들고, 선택한 저장소 하나의 Contents 권한을 읽기·쓰기로 설정하세요.
  3. 편집기의 ‘GitHub에 보관’에 계정/저장소와 토큰을 입력하세요. 저장 전에 대상과 공개 여부의 의미를 확인합니다.

기록 파일은 hanlint/workspace.json입니다. 토큰은 현재 탭의 메모리에만 있고, 기록 파일이나 브라우저 저장소에는 들어가지 않습니다. 새로고침하거나 연결 정보를 지우면 토큰을 다시 입력해야 합니다.

GitHub에 기존 기록이 있으면 먼저 가져와야 합니다. 가져오기는 브라우저의 전체 기록을 교체하므로, 현재 기록을 보관하려면 내보내기를 먼저 하세요. 다른 기기에서 파일이 바뀌면 저장 충돌을 알리고 덮어쓰지 않습니다. 여러 기기의 동시 편집을 자동으로 합치지 않습니다.

수정 기록과 승인 고침

수정본을 기록했다고 좋은 문장의 정답으로 배우지는 않습니다. ‘고침 기억’에서 원문과 수정문의 뜻을 확인한 뒤 승인한 고침만 재사용 후보가 됩니다. 같은 원문, 규칙, 글 종류와 문맥 조건이 맞을 때 다시 제안하며, 자동으로 적용하지 않습니다. 승인을 지우면 그 고침의 재사용이 멈춥니다.

원문 보호는 숫자, URL, 인라인 코드, 링크 목적지와 H2 제목 순서를 비교합니다. 숫자의 대상 관계나 사실의 진실, 의미 보존과 자연스러움까지 판단하지 않습니다. 확인되지 않은 수정 사례를 기본 규칙에 자동 반영하지 않습니다.

개선 사례 기여하기

‘내 기록’에서 수정본 하나를 골라 사례 파일을 내보낼 수 있습니다. 원문과 수정 후 전문이 포함되므로 공유 전에 개인정보와 비공개 내용을 확인해 주세요. 파일을 받는 것만으로 외부에 제출되지 않습니다. 검토한 파일을 GitHub Issues에 첨부하면 기존의 검토 절차로 다룹니다. ‘이 지적은 맞지 않아요’로 남긴 판단은 개인 기록 내보내기에 포함됩니다.

내 계정에서 사이트 운영하기

한린트 저장소를 Fork한 뒤 Settings → Pages → Source를 GitHub Actions로 설정하세요. Actions를 허용하고 pages 워크플로를 실행하면 자기 계정의 Pages 주소로 배포됩니다. main의 변경이 검증을 마치면 사이트에 반영됩니다. 원고용 비공개 저장소와 사이트 소스 저장소는 별도로 둘 수 있습니다.

한린트 npm 코어는 빌드 없이 같은 ESM 소스를 사용합니다. 페이지는 이를 정적 배포 폴더에 조립해 제공합니다. Python의 모든 CLI 명령을 웹에 옮긴 것은 아니며, 이 화면은 검사·고침·원문 보호·지문 요약·승인 고침 후보와 개인 기록을 제공합니다.
