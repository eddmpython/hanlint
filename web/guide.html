한린트 사용 안내

고친 글을 남기고,
내 고침을 기억하세요.

글을 넣으면 지적이 바로 나옵니다. 고친 뒤에는 전후를 비교하고,
다시 쓸 고침을 직접 골라 남길 수 있습니다.

처음 쓰기수정본 기록고침 기억 GitHub 보관사례 기여내 사이트 운영문제 해결

01 · 글 다듬기

예문을 내 글로 바꾸면 시작입니다

  1. 원문 넣기. 왼쪽 원문에 글을 붙여 넣거나 파일 열기로 원고를 엽니다. 오른쪽에 검사 결과가 나옵니다.
  2. 글 종류 고르기. 블로그, 기술 문서, 보고서 등 원고에 맞는 종류를 고릅니다. 같은 문장도 글의 목적에 따라 다른 규칙으로 확인합니다.
  3. 결과 살펴보기. 결과에 문장, 이유와 고친 본보기가 바로 나타납니다. 같은 문장의 지적은 함께 보여 줍니다. 고침 버튼을 누르면 아래 수정본에 반영됩니다.
  4. 아래에서 직접 다듬기. 아래 수정본에는 원문이 미리 담겨 있습니다. 글을 바로 고쳐 쓰세요. 수정 중에는 원문이 보존되고 오른쪽 결과도 수정본을 검사합니다. 다른 글은 새 글이나 파일 열기로 시작하세요.
  5. 전후 확인하기. 전후 비교로 두 글을 함께 보고, 원문 보호에서 숫자와 링크, 코드와 H2 제목 순서의 변화를 확인합니다.

첫 화면은 기기의 다크·라이트 설정을 따릅니다. 우측 상단의 해·달 버튼을 한 번 누르면 바뀌고, 선택한 테마는 다음 방문과 사용 안내에도 이어집니다.

원문과 수정본은 따로 남습니다

새 글로 시작해 왼쪽에 초안을 쓴 뒤, 아래에서 고치세요. 수정본을 전체 선택해 다른 글을 붙여 넣어도 원문은 바뀌지 않습니다. 수정하면 원문 보호 결과와 기억할 고침이 수정본 아래에 바로 나옵니다.

원문 보호는 표면의 변화를 비교합니다. 숫자가 가리키는 대상, 사실의 진실과 문장의 뜻까지 판단하지는 않습니다. 지적이 없어도 한 번 읽고 마무리해 주세요.

02 · 내 기록

지금 글과 수정본을 함께 보관합니다

편집 중인 원고는 이 브라우저에 임시 보관됩니다. 수정본 기록을 누르면 수정 전 원문과 현재 글, 글 종류, 검사 버전, 선택한 수정 이유와 수정 방식을 기록합니다. 수정본 아래의 내 기록과 GitHub에 보관으로 바로 이동할 수 있습니다. 수정 메모와 방식은 화면에서 선택하고 수정본 기록을 한 번 누르면 저장됩니다.

필요한 내용에 맞춰 내보내기
선택남는 내용
원고 받기현재 글을 마크다운 파일로 받습니다.
내 기록에서 내보내기원고, 수정본, 승인 고침과 지적에 대한 판단을 JSON 파일로 받습니다. 다른 브라우저에서 가져올 수 있습니다.
사례 내보내기선택한 수정본의 원문과 수정 후 전문, 수정 이유와 방식을 기여용 파일로 받습니다.

원고는 60,000자, 수정본은 기록 파일 하나에 100개, 기록 파일은 900 KB까지 다룹니다. 한도에 닿으면 내보낸 파일을 확인한 뒤 이전 기록을 정리하세요. 오래된 글을 자동으로 삭제하지 않습니다.

가져오기는 전체 기록을 교체합니다

파일과 GitHub에서 가져올 때 모두 현재 기록을 먼저 내보내세요. 브라우저 데이터 삭제나 비공개 창 종료로도 기록이 사라질 수 있습니다.

03 · 고침 기억

저장과 승인은 다른 단계입니다

수정본을 남긴 것만으로 좋은 문장의 정답이 되지는 않습니다. 고침 기억에서 원문과 수정문을 읽고, 뜻이 맞는 고침을 승인하면 다음에 다시 제안할 수 있습니다.

승인한 고침은 같은 원문, 규칙, 글 종류와 문맥 조건이 맞을 때 후보로 나옵니다. 자동으로 적용하지 않으며, 승인을 지우면 재사용이 멈춥니다. 모든 수정에서 승인할 후보가 나오는 것은 아닙니다.

개인 승인은 나의 작업에만 쓰입니다. 확인되지 않은 수정 사례를 한린트의 기본 규칙이나 공통 학습 데이터에 자동으로 넣지 않습니다.

04 · GitHub에 보관

여러 기기에서 같은 기록을 이어 보세요

  1. 원고용 저장소 만들기. 내 GitHub에 저장소를 만듭니다. 원고를 공개하지 않으려면 비공개로 만드세요.
  2. 저장소 하나의 토큰 만들기. Fine-grained personal access token에서 해당 저장소를 선택하고 Contents: Read and write 권한을 줍니다.
  3. 연결하기. 편집기의 GitHub에 보관에서 계정/저장소와 토큰을 입력합니다. 저장 대상과 공개 여부를 확인합니다.
  4. 가져오거나 저장하기. 기존 기록이 있으면 먼저 가져옵니다. 새 저장소라면 바로 저장할 수 있습니다. 다른 기기에서는 같은 저장소를 입력하고 가져오기를 선택합니다.

기록은 저장소의 hanlint/workspace.json에 남습니다. 토큰은 현재 탭의 메모리에만 있고, 기록 파일이나 브라우저 저장소에는 들어가지 않습니다. 새로고침하거나 연결 정보를 지우면 다시 입력해야 합니다.

다른 기기에서 바꾼 기록이 있다면

충돌을 알리고 저장을 멈춥니다. 지금 글을 파일로 보관한 뒤 최신 기록을 가져와 주세요. 여러 기기의 변경을 자동으로 합치지는 않습니다.

05 · 함께 개선하기

좋은 수정과 틀린 지적을 알려 주세요

지적이 맞지 않으면 이 지적은 맞지 않아요로 판단을 남길 수 있습니다. 이 판단은 개인 기록에 포함되며, 한린트 운영자에게 자동 전송되지 않습니다.

공유할 수정본은 내 기록에서 사례 파일로 내보내고, GitHub Issues의 맞는 양식에 첨부해 주세요. 어디가 왜 나아졌는지 함께 적으면 검토에 도움이 됩니다.

사례 파일에는 원문과 수정 후 전문이 들어갑니다. 공유 전에 개인정보와 비공개 내용을 확인해 주세요. 사례 제출 뒤에도 검토를 거쳐야 공통 규칙에 반영됩니다.

06 · 내 사이트 운영

내 GitHub Pages에도 띄울 수 있습니다

  1. 한린트 저장소를 Fork합니다.
  2. 저장소의 Settings → Pages → Source에서 GitHub Actions를 선택합니다.
  3. Actions 탭에서 워크플로 실행을 허용한 뒤, pages → Run workflow를 실행합니다.
  4. 검사와 배포가 끝나면 Pages 설정에 표시된 내 사이트 주소를 엽니다. 이후 main 변경도 같은 검사를 거쳐 배포됩니다.

사이트 소스 저장소와 원고를 보관할 비공개 저장소는 별도로 둘 수 있습니다. 사이트를 Fork할 때 원고나 토큰을 소스에 넣을 필요는 없습니다.

디자인, 제작자 링크와 로컬 실행을 바꾸려면 개발·배포 안내를 참고하세요.

도움이 필요할 때

자주 막히는 자리

기록이 저장되지 않거나 다른 탭 안내가 나와요

현재 원고와 기록을 먼저 파일로 내보내세요. 용량 한도나 브라우저 저장 권한을 확인하고, 다른 탭에서 같은 기록을 바꿨다면 새로고침해 최신 내용을 엽니다. 한 원고는 한 탭에서 편집해 주세요.

GitHub 인증이나 저장에 실패해요

계정/저장소 이름, 토큰 만료와 선택한 저장소의 Contents 읽기·쓰기 권한을 확인하세요. 기존 파일 안내나 충돌이 나오면 현재 기록을 내보낸 뒤 먼저 가져옵니다. 조직 저장소는 조직의 토큰 승인도 필요할 수 있습니다.

가져온 파일을 읽을 수 없어요

‘내 기록’에서 내보낸 한린트 기록 JSON인지, 900 KB 이하인지 확인하세요. 원고 마크다운은 ‘파일 열기’로 열고, 기여용 사례 파일은 기록 가져오기에 쓰지 않습니다.

검사가 계속 준비 중이에요

현재 원고를 복사하거나 파일로 받은 뒤 새로고침해 주세요. 처음 열 때 검사 자료를 받아야 하므로 네트워크 연결도 확인합니다. 계속 실패하면 브라우저 이름과 표시된 오류를 Issues에 알려 주세요.

검사와 수정 비교는 브라우저 안에서 실행합니다. 글을 입력하는 것만으로 원고가 외부에 전송되지는 않습니다. 사이트 파일 요청, 외부 링크 방문과 사용자가 선택한 GitHub 저장은 별개입니다.
