# 탐침

여기는 게이트가 아니다. **알아내는 자리**다.

게이트는 이미 아는 것을 지키고 탐침은 모르는 것을 알아낸다. 규칙이 실제 글에서 얼마나 맞는지, 지적을
받은 사람이 실제로 고칠 수 있는지, 어떤 자리가 도구의 손을 벗어나는지는 fixture 로 알 수 없다.
fixture 는 구현이 의도대로 도는지를 증명하지 그 의도가 실제 글에서 맞는지를 증명하지 않는다.

dartlab 의 `tests/_attempts/` 에서 가져온 꼴이다. 주제 하나가 폴더 하나이고, 안에 탐침 스크립트와
`*_log.md` 가 있다. 로그에는 언제 무엇을 재서 어떤 수가 나왔는지를 적는다.

## 규칙

- **pytest 가 수집하지 않는다.** `python_files = ["test*.py"]` 라 `probe*.py` 는 안 걸린다. 탐침은
  초록불을 만드는 것이 아니라 수를 만드는 것이므로 게이트에 섞지 않는다.
- **탐침은 판정하지 않는다.** 임계를 넘었는지 세지 말고 분포를 적는다. 그 수를 보고 사람이 정한다.
- **로그에 날짜와 대상과 커밋을 적는다.** 살아 있는 저장소를 재면 다음 주에 다른 수가 나온다.
  실측 3회차에서 실제로 겪었다 (`memory/evidence/dogfoodRound3.md`).
- **탐침이 알아낸 것이 규칙을 바꾸면 그 근거는 `memory/evidence/` 로 간다.** 여기는 잰 기록이고
  거기는 판단이다.

## 지금 있는 것

탐침 하나가 폴더 하나다. 그 안에 스크립트와 로그가 짝으로 있다.

| 폴더 | 무엇을 재나 |
|---|---|
| `fixReach/` | 지적 가운데 기계가 고쳐 주는 비율. 나머지는 글쓴이의 몫으로 남는다 |
| `exemplarLift/` | 같은 수정 과제에서 본보기 유무만 바꿔 규칙 해결과 새 error 를 견준다 |
| `koreanStyleBooks/` | 한국 글쓰기 책들이 드는 자리가 실제 글에 얼마나 있나. 규칙이 될 만한지 |
| `patchMemory/` | cue 기반 선택을 폐기하고 승인 원문 완전 일치 재생만 일반 본보기보다 안전한지 |
| `operationMemory/` | 공개 Git 고침에서 뽑은 작은 표면 연산이 다른 원문에서도 사실과 뜻을 지키며 향상되는지 |
| `writingLift/` | 일곱 종류 완성 글에서 writingPacket, 반복 수정, 사실 가드가 실제로 사실과 자연스러움을 높이는지 |
| `factContract/` | 구조화 brief로 쓴 일곱 종류 결과에서 guard가 사실 표면 실패를 결정적으로 드러내는지 |
| `blindWritingArena/` | 일곱 종류가 안전 검사, 익명화, 평가 기록과 집계의 같은 계약을 지나는지 |
| `rhetoricalBlueprint/` | 원문 없는 종류별 구조 예산이 기본 brief보다 안전하게 쓸 수 있는 결과를 만드는지 |
| `evidenceLedger/` | v2 근거 원장이 사실 연결·출처 판·조각 해시의 누락과 변조를 결정적으로 막는지 |
