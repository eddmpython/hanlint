# writingArena v1 실제 모델 탐침

날짜: 2026-08-31

## 생성 전략 탐침

같은 자체 작성 일곱 장르 brief로 `plainBrief`와 `readerTaskDraftV1`을 각각 한 번 생성했다. 후보 절차는
독자가 글 뒤에 알아야 하거나 느끼거나 해야 할 한 가지를 먼저 잡고, 각 원자 사실을 필요한 자리에서 한
번씩 쓰며, 사실 목록을 되풀이하지 않고 관계를 드러내도록 했다. 두 조건 모두 재시도와 손선택은 없었다.

- Ollama 0.23.2
- 모델 `qwen3:8b`
- 모델 digest `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`
- `temperature=0`, `seed=42`, thinking 끔
- prompt token 8,988개, 생성 token 2,400개, 전체 모델 처리 77.536초
- manifest 파일 SHA256 `df89042bfdfc77f0673d5f43dec4d1f884e1ce6ea9f5364ac1966c0a6ae4c4c0`
- 원응답 파일 SHA256 `cc32b9c0fa1815e0619c8e5febd4576a53da9be75403e45907d6e363b6e3cd42`
- 결과 파일 SHA256 `6824f4de0e667c1f4f268f9946d8e794779dceb7d1358f77a4b04f3df2f6cc02`

| 항목 | plainBrief | readerTaskDraftV1 |
|---|---:|---:|
| 사실 표면 충족 | 7/7 | 7/7 |
| lint error 0 | 3/7 | 7/7 |
| 전체 자동 계약 충족 | 3/7 | 7/7 |

안전 결과는 후보 안전 승 4쌍, 둘 다 안전 3쌍이었다. 기준의 네 오류는 보고문 cliche 1건, 기술 문서,
안내서와 백과의 translationese 각 1건이었다. 후보에는 error가 없었다. 이 실행에서 후보 절차는 자동
안전 계약을 분명히 개선했고, 세 쌍을 사람 눈가림 선호 평가로 올릴 수 있게 했다. 그러나 자동 계약은
자연스러움과 독자 효용을 판정하지 않으므로 7대 3을 글 품질 승리로 부르지 않는다.

## 자동 심사기 순서 탐침

고정 파일럿의 일곱 글 쌍을 정방향과 역방향으로 각각 독립 제시했다. 사람 합의가 없으므로 정확도와
calibration은 계산하지 않았다.

- 같은 Ollama와 모델 digest, `temperature=0`, `seed=42`, thinking 끔
- presentation 14개
- 모델 입력에는 내부 presentation ID, case ID와 정방향·역방향 표시를 주지 않고 context와 두 글만 줌
- prompt token 8,444개, 생성 token 2,272개, 전체 모델 처리 79.462초
- manifest 파일 SHA256 `1036009bf693ff99a101b7059835e5b0e20f80ba5087697a058bbc0110407618`
- 원응답 파일 SHA256 `9aed51fc80dd203bf06cc9640372fd99633dcba5ee2d4d5b342d215f7de14d92`
- 결과 파일 SHA256 `7fae57d05854fc4fa598f7a7de48376cd4db58941b598654c8a35e6ed01982de`

소설 역방향 1개는 content를 pass가 아닌 값으로 두고도 선호를 기권하지 않아 제품 계약이 원응답을
거부했다. 탐침 집계에서는 이 presentation 전체를 fail-closed 기권으로 만든 사본만 사용했다.

| 차원 | 비교 가능한 쌍 | 순서 일치 | 순서 일관성 | 전체 사용 가능 범위 |
|---|---:|---:|---:|---:|
| content | 12/14 | 12/12 | 1.0000 | 0.8571 |
| 자연스러움 | 6/7 | 5/6 | 0.8333 | 0.7143 |
| 명료성 | 6/7 | 6/6 | 1.0000 | 0.8571 |
| 독자 과업 | 6/7 | 3/6 | 0.5000 | 0.4286 |
| 목소리 | 0/7 | 0/0 | 계산 안 함 | 0.0000 |

일치한 자연스러움 5건, 명료성 6건과 독자 과업 3건의 선택은 전부 tie였다. 같은 모델은 명료성에서는
좌우를 바꿔도 안정적으로 무승부를 냈지만, 자연스러움과 특히 독자 과업에서는 순서에 따라 답이 자주
달라졌다. 높은 일관성도 정답을 뜻하지 않고, 모두 tie인 심사기는 전략을 구별하지 못할 수 있다.

## 판정

`readerTaskDraftV1`은 이번 일곱 과제에서 다음 사람 평가로 갈 수 있는 안전한 후보를 늘렸다. 그래서
스킬의 초안 절차에는 반영할 가치가 있다. 반면 `qwen3:8b` 단독 심사기는 독자 과업 선호에 바로 쓸 수
없다. 실제 사람 세 명 이상의 독립 판정과 차원별 합의를 받은 뒤에만 자동 심사기의 정확도와 calibration을
계산한다. 현재 hanlint는 자연스러운 글을 보장했다고 말할 단계가 아니지만, 그 주장을 빠르게 반증하거나
검증할 실행 계약을 갖추게 됐다.
