# writingLift 로그

## 2026-08-31. 질문과 경계

hanlint의 문장 규칙, 승인 패치와 작은 표면 연산은 국소 수정에서 효과를 냈다. 그러나 사용자가 묻는 것은
더 크다. `writingPacket`을 실제 모델에 주면 일곱 종류의 완성 글에서 일반 요구만 준 것보다 자연스럽고
유용하며 사실을 지킨 글이 나오는가.

공개 글의 문장을 프롬프트에 복사하지 않았다. 블로그, 보고서, 기술 문서, 안내서, 수필, 소설, 백과의
합성 과제 일곱 개를 만들고 독자, 과업, 허용 사실, 필수 표면, 숫자, 금지 주장, 글자 수를 고정했다. 따라서
강한 글 데이터베이스는 생성 재료가 아니라 분포 비교와 평가 자료다. 이번 탐침의 과제 원문도 제품 데이터로
승격하지 않는다.

기준판은 `b8e5e940e31d911286845c0149d03b0143d9949e`다. 생성기는 로컬 `qwen3:8b`, digest
`500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`, temperature 0, seed 42,
`num_predict=1200`, `think=false`다. 로컬에 다른 모델이 없어 생성기와 판정기가 같은 모델이다. 이 결과는
사람 평가나 교차 모델 합의가 아니다.

## 선행 연구에서 가져온 평가 계약

- [Judging the Judges](https://aclanthology.org/2025.ijcnlp-long.18/)는 LLM 판정의 위치 편향이 무작위가
  아님을 대규모로 보였다. 모든 쌍을 A/B 양쪽 순서로 평가했다.
- [Illusions of the Gold Standard](https://aclanthology.org/2026.acl-long.635/)는 장문 생성 사람 평가의
  프로토콜 누락을 지적한다. 모델 digest, 맥락, rubric, 순서, 반복과 원시 판정 hash를 모두 적는다.
- [KatFishNet](https://aclanthology.org/2025.acl-long.1030/)은 한국어 LLM 글의 쉼표 사용과 품사 다양성
  차이를 보고했지만, 쉼표를 줄이라고 시킨 결과가 더 사람다운 글을 보장하지 않았다고 밝혔다. 쉼표 문장
  비율과 어휘·리듬 지문은 진단값으로만 기록하고 점수나 작법 규칙으로 쓰지 않는다.
- [KoSEnd](https://aclanthology.org/2025.acl-srw.29/)는 한국어 종결 표현의 자연스러움을 별도 주석으로
  다룬다. 자연스러움은 사실 보존이나 과업 효용과 한 점수로 합치지 않는다.
- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)는 장문을 원자 사실로 나눠 사실성을 평가한다.
  [D-FActScore](https://aclanthology.org/2024.findings-acl.160/)는 개별 사실이 참이어도 서로 다른 개체를
  섞으면 전체 서술이 거짓일 수 있음을 보였다. 필수 문자열만 세지 않고 판정 rubric에서 사실 관계도 본다.
- [TRUE](https://aclanthology.org/2022.naacl-main.287/)는 사실 일관성 측정의 예시 단위 정확도와 서로 다른
  접근의 보완성을 비교한다. 결정적 표면 가드와 별도 모델 판정을 분리한다.
- [Style Transfer 평가 연구](https://aclanthology.org/2023.findings-acl.687/)와
  [NAACL 2019의 내용·문체·유창성 분리](https://aclanthology.org/N19-1049/)를 따라 사실 보존, 과업 효용,
  한국어 자연스러움, 조직, 간결성을 따로 판정한다.

모델 판정은 조건 이름을 숨긴다. 각 후보와 일반 brief를 두 seed `314159`, `271828`과 양쪽 순서로 모두
네 번 비교한다. 네 판정이 모두 후보 또는 모두 baseline일 때만 그 차원을 합의로 센다. 종합 후보 선호도
후보의 결정적 사실 표면 가드가 통과하고 hanlint error가 baseline보다 늘지 않아야 안전 승이다.

## v1 완성 글 실험

조건은 일반 brief, 짧은 작법 규칙, v1 `writingPacket`, v1 패킷 뒤 한 번 수정이다. 모두 28개 완성 글과
84개 블라인드 판정을 만들었다.

| 조건 | 사실 표면 | 길이 | error 0 | error | 평균 글자 | 안전 승/패 |
|---|---:|---:|---:|---:|---:|---:|
| 일반 brief | 2/7 | 0/7 | 5/7 | 2 | 365.0 | 기준 |
| 짧은 규칙 | 1/7 | 0/7 | 4/7 | 4 | 402.0 | 0/0 |
| v1 writingPacket | 0/7 | 0/7 | 3/7 | 7 | 1325.6 | 0/2 |
| v1 한 번 수정 | 0/7 | 0/7 | 3/7 | 12 | 2152.4 | 0/1 |

실패는 미묘한 문체 차이가 아니었다. 모델은 JSON을 설명하고 `patterns.example`의 `report.csv`,
`link.png`, 33픽셀, pandas 3.7초와 Polars 0.18초를 결과에 복제했다. 소설 요구의 글자 수 650과 950을
사건의 메시지 수와 초로 만들었다. 백과는 누리섬솔새 대신 다람쥐를 쓰거나 한국어 문형을 중국어로
설명했다. 수정 반복은 이 오염을 더 길게 되풀이했다.

## 실패 원인 ablation

일반 brief 원시 출력은 그대로 재사용했다. full packet의 끝에 원문을 다시 둔 조건, 공통 `patterns`만
제거한 조건, 비교와 예시를 모두 뺀 최소 JSON, JSON을 쓰지 않은 짧은 실행 프롬프트를 추가로 비교했다.

| 조건 | 사실 표면 | error 0 | error | 평균 글자 | 안전 승 |
|---|---:|---:|---:|---:|---:|
| 일반 brief | 2/7 | 5/7 | 2 | 365.0 | 기준 |
| 원문을 끝에 반복 | 1/7 | 4/7 | 3 | 309.4 | 0 |
| 공통 patterns 제거 | 2/7 | 6/7 | 1 | 399.6 | 0 |
| 최소 JSON | 0/7 | 6/7 | 1 | 266.9 | 0 |
| 짧은 실행 프롬프트 | 0/7 | 4/7 | 4 | 296.9 | 0 |

공통 문형을 빼면 v1의 다른 글 예시 누출과 장문 JSON 설명은 사라졌다. 원문을 뒤에 반복하거나 JSON을
줄이는 것만으로는 사실 통과가 늘지 않았다. 문형 제거는 현재 제품보다 분명히 안전하지만 일반 brief보다
좋은 글을 만들었다는 근거는 아니다.

## 사실 가드와 재작성 보류

공통 문형을 뺀 초안을 고정했다. 일반 재시도, 빠진 필수 표면·숫자·금지 주장·길이만 알려 준 수정,
같은 가드에 실제 hanlint error를 더한 수정, 전체 사실 원장을 주고 다시 쓴 조건을 비교했다.

| 조건 | 사실 표면 | 길이 | error 0 | error | 안전 승 |
|---|---:|---:|---:|---:|---:|
| 수정 없음 | 2/7 | 0/7 | 6/7 | 1 | 기준 |
| 일반 재시도 | 0/7 | 1/7 | 6/7 | 1 | 0 |
| 빠진 사실 가드 | 2/7 | 0/7 | 5/7 | 3 | 0 |
| 사실 가드와 lint | 2/7 | 0/7 | 5/7 | 3 | 0 |
| 전체 사실 원장 재작성 | 3/7 | 0/7 | 3/7 | 5 | 0 |

일반 재시도는 맞던 사실도 잃었다. 사실 가드는 라벨 안내 한 건의 요구 밖 숫자를 없앴지만 수필의
`1.8 km`를 잃었다. 사실 원장은 통과를 한 건 늘리는 대신 error를 네 건 늘렸다. 모든 후보의 종합 판정은
네 반복에서 합의되지 않았다. 결정적 가드가 재작성 모델을 안전하게 만든다고 승격하지 않는다.

## 제품 v2 재검증

v2 `writingPacket`은 공통 `patterns`를 제거하고 버전을 2로 올렸다. `comparison`은 진단 자료이며 결과
글의 사실이나 문장 재료로 쓰지 않는다는 계약과, 패킷이 사실·유용성·자연스러움을 보장하지 않는다는
검증 경계를 넣었다. 변경한 제품 코드로 28개 글과 84개 판정을 다시 만들었다.

| 조건 | 사실 표면 | 길이 | error 0 | error | 평균 글자 | 안전 승/패 |
|---|---:|---:|---:|---:|---:|---:|
| 일반 brief | 2/7 | 0/7 | 5/7 | 2 | 372.1 | 기준 |
| 짧은 규칙 | 1/7 | 0/7 | 4/7 | 4 | 405.3 | 0/0 |
| v2 writingPacket | 1/7 | 1/7 | 7/7 | 0 | 433.0 | 0/0 |
| v2 한 번 수정 | 2/7 | 1/7 | 7/7 | 0 | 396.6 | 0/0 |

v2는 v1의 예시·프로파일 누출과 error 증가를 없앴다. 그러나 일반 brief보다 안전하게 이긴 과제는 없고
블라인드 종합 판정은 대부분 불안정했다. 따라서 `writingPacket`은 결정적 근거와 정확 고침을 전달하는
패킷이지 자연스러운 한국어를 직접 생성하거나 보장하는 작법기계가 아니다. 모델 수정은 한 번마다 원문
사실을 대조하고, error 0은 별도 사실·과업·자연스러움 평가를 대신하지 않는다.

## 다음 연구 방향

다음 작법기계는 더 많은 좋은 문장을 프롬프트에 넣는 방향이 아니다.

1. 잘 쓴 글 데이터베이스는 출처·라이선스·종류·독자·과업과 함께 평가와 분포 층에 둔다. 생성 실행 층에는
   승인 원문 완전 일치 패치와 보호 가드를 통과한 작은 연산만 보낸다.
2. 사용자 brief를 원자 사실, 개체·관계, 필수 표면, 허용 숫자, 금지 추론으로 구조화하고 초안과 결과의
   관계 보존을 결정적 검사와 사람 판정이 함께 확인한다. 이번 사실 가드처럼 곧바로 자동 재작성하지 않는다.
3. 자연스러움은 한국어 종결, 쉼표, 어휘 다양성, 조직을 진단하되 사람 선호로 보정한다. 한 지문을 품질
   점수로 부르지 않는다.
4. 다음 생성 실험은 서로 다른 모델과 사람 평가자를 포함하고, 고정 holdout과 공개 가능한 합성 brief에서
   먼저 순향상을 보여야 한다. 그전에는 hanlint를 생성기나 자연스러움 보장기로 부르지 않는다.
