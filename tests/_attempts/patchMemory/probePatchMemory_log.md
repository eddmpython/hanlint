# patchMemory 로그

## 2026-08-30. 승인 고침의 선택과 기권

일반 본보기 30쌍에서 안전한 수정 성공의 순향상이 0이었다. 다음 실험은 본보기를 더 넣는 대신 글쓴이가
승인한 국소 고침을 `rule`, 문서 `preset`, 지적의 `cue`, 문장 직전 `reader` 상태가 모두 맞을 때만 준다.
하나라도 다르면 이유만 주는 조건과 같은 프롬프트로 기권한다.

승인 전후 짝은 MDN 한국어 문서 Git 이력에서 찾았다. 12,200개 깊이 안의 한국어 관련 커밋 272개 중
자동 동기화, 포매터, 링크 일괄 변경을 빼고 수동 수정 200개를 `hanlint learn`으로 비교했다. 20개 넘는
파일을 한꺼번에 바꾼 커밋 8개도 제외했다. 후보 9건 가운데 뜻을 보존한 국소 고침으로 직접 확인할 수 있는
두 건만 쓴다.

- `에 의해` 피동에서 행위의 주체를 앞으로 옮긴 문장. MDN commit
  `742d9a9829df079fc9de3096cfac245344ce1bc3`
- `필요할때`를 `필요할 때`로 띄운 문장. MDN commit
  `01a8e49f8540454a5a1a8189f5f3d1408166332c`

둘 다 Mozilla Contributors의 CC-BY-SA-2.5 문서다. 새 번역, 문단 전체 교체, 내용 삭제는 커밋 승인이
있어도 같은 뜻의 국소 패치가 아니므로 제외했다.

먼저 1,600편, 문장 지적 44,457건에서 조건의 도달 범위를 쟀다. 문장 전체를 cue로 쓰면 같은 rule,
preset, cue, reader가 두 번 이상 나온 지적은 5,345건이었다. 규칙 이유의 인라인 코드나 자동 고침
fragment 가운데 두 글자 이상인 국소 표지를 쓰고 나머지만 문장 전체로 돌리면 22,140건이었다. reader를
빼면 22,683건이라 안전 조건 하나를 버려 얻는 범위는 543건뿐이었다.

## 같은 날. 첫 선택 계약의 폐기

말뭉치에서 규칙마다 exact, reader mismatch, cue mismatch를 최대 네 건씩 고정했다. spacing exact는
두 건뿐이라 복제하지 않았다. 총 22과제는 exact 6, reader mismatch 8, cue mismatch 8이다. manifest
SHA256은 `b33ab8d617bd88dba678bce6d8fcdc9eb3d8e69a0f71dd50f6ab339da2e49975`다.

Ollama 0.23.2의 `qwen3:8b` Q4_K_M을 썼다. digest는
`500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`, 크기는
5,225,388,164바이트다. `think=false`, `temperature=0`, `seed=42`, `num_predict=512`는 이전 실험과
같다. 세 조건 66응답 중 기권한 selectedPatch 16건은 reasonOnly와 프롬프트가 같아 같은 출력을
재사용했다. 실제 모델 호출은 50회다. 원시 응답 SHA256은
`79151e4b8689e023bb8b39241476914ab5290f1e3b82fbab0113ab64fc559751`, 뜻 보존 판정 SHA256은
`d2157ff0097c7c3e421c90a2d3f8aed86dcbe9bb4381007e3bf36d5631f4817d`다.

```text
                 규칙 해결  새 error  뜻 보존  세 조건 충족
reasonOnly          18/22        0건     18/22       15/22
blindExemplar       18/22        0건     19/22       16/22
selectedPatch       17/22        0건     17/22       14/22

선택 패치 대 일반 본보기: 선택만 성공 0, 일반만 성공 2, 같은 결과 20
exact 여섯 짝:          선택만 성공 0, 일반만 성공 0, 같은 결과 6
```

첫 계약은 승격하지 않는다. `에 의해`라는 cue와 reader가 같아도 승인 고침은 도구를 나타내는 `로` 변환이고
대상 문장은 행위자를 주어로 세우는 변환일 수 있었다. 선택 패치가 `스테이트풀셋의 serviceName`에서 소유
관계를 지운 응답도 한 건 나왔다. cue는 결함 표지이지 같은 손동작의 증거가 아니다. 다음 계약은 전후 차이에서
뽑은 변환 조각이나 규칙이 허용한 연산까지 맞아야 한다.

## 같은 날. 공개 저자 이력의 승인과 재사용 증거

공개 MIT 저장소 `eddmpython/eddmpython`의 commit
`8531fdf1c03d9f5a1733d6f769a81ce0ead2d45b`에서 저자와 평가자 루프를 거친 세 국소 고침을 확인했다.

- `다음으로`를 앞에서 끝낸 설치 결과와 다음 행동으로 바꾼 `fillerOpener`
- `핵심은`을 실제로 작동하는 코드 세 줄의 이름으로 바꾼 `cliche`
- `이것을`을 앞 코드의 `Set` 클래스로 바꾼 `danglingDeixis`

그대로 재사용할 표본이 있는지도 따로 쟀다. 기준 말뭉치에서 블로그는 10편뿐이고 exact가 모두 0이었다.
0BSD 저장소 `yjksw/yjksw.github.io` commit
`7962532871d7837a6e96474b577dd4e2ed5d7b48`의 블로그 87개 커밋도 `hanlint learn`으로 훑었다. 후보는
2건뿐이었다. 하나는 숫자 800명을 1600명으로 바꾼 내용 갱신이고, 하나는 문장 뒤에 새 링크 안내를 붙인
변경이었다. 커밋 승인이 있어도 뜻 보존 국소 고침이 아니므로 둘 다 패치에서 제외했다. 승인 이력과 다른
문장에 재사용할 수 있다는 증거는 같은 것이 아니다.

## 같은 날. 원문 완전 일치 재생의 승격

유사 문장으로 넓히는 대신 선택 계약을 좁혔다. NFC로 조합하고 연속 공백과 줄바꿈만 눕힌 원문이 승인
`before`와 같고, `rule`, `preset`, `cue`, `reader`까지 모두 같으며 패치가 하나일 때만 승인 `after`를
모델 호출 없이 그대로 재생한다. 원문이 다르면 기권한다.

승인 원문 3건과 0BSD 블로그에서 규칙별로 고정한 원문 불일치 2건씩, 모두 9과제다. 말뭉치 파일 digest는
`c1e9da8c2eac6b15438b8bded32facc36d14c81a856770fe168f406c347cb8d2`, manifest SHA256은
`2f2f5036f4cd99dee66435ab3d1d10143e07de2c6cba444e43433ecdaeb993f0`다. 모델과 옵션은 첫 실험과
같고 실제 모델 호출은 18회다. 원시 응답 SHA256은
`8c0933474ab4a8775bdc72185d9a625fff7534481ce38761267751e55e4a2108`, 뜻 보존 판정 SHA256은
`6d4237df7ce0ae8f49162cdb3dca4e26a680003d181136ad93786583e581eb03`, 점수 JSON SHA256은
`7b91f2f8789e3f2fb078201043eef35e879c86df46a94b41d6049dd61359ef31`다.

```text
                 규칙 해결  새 error  뜻 보존  세 조건 충족
reasonOnly            3/9        0건       8/9         2/9
blindExemplar         3/9        0건       8/9         3/9
selectedPatch         5/9        0건       8/9         4/9

전체:          선택만 성공 2, 일반만 성공 1, 같은 결과 6
원문 완전 일치: 선택만 성공 2, 일반만 성공 0, 같은 결과 1
원문 불일치:   선택만 성공 0, 일반만 성공 1, 같은 결과 5
```

승격 범위는 원문 완전 일치 재생뿐이다. 세 exact 가운데 `cliche`와 `danglingDeixis`는 일반 본보기가
지적을 해결하지 못했지만 승인 결과 재생은 해결했고 뜻을 보존했다. 불일치 문장에는 승인 패치를 주지
않는다. 9과제는 일반화 성능을 주장할 표본이 아니다. 유사 문장 검색, cue 기반 전이, 변환 추론은 계속
실험 대상으로 남기고 제품 계약에는 넣지 않는다.

제품 투영에서는 이 계약을 더 좁혔다. `learn`이 승인 전후의 인라인 마크다운을 보존하고, 선택할 때도
마크다운 원문 `sourceText`와 표식을 걷은 `sentence`를 둘 다 맞춘다. 실험의 exact 세 문장은 인라인
마크다운이 없는 평문이라 결과와 표본 수는 바뀌지 않는다. 원문 표식이 다르면 추가로 기권한다.
