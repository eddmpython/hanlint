# fixReach 로그

## 2026-08-27 밤. 본보기를 넣기 전

대상은 eddmpython `955e2ed` 의 발행본 다섯 편 스냅숏이다 (살아 있는 저장소라 커밋을 고정해서 잰다).
설정은 `preset = "blog"` 에 `keywordField` 와 `introFields` 와 `endingFields` 를 채운 것이다.

```text
글     5편, 지적 104건 (error 14)

fix      0건 ( 0.0%)  기계가 원문에 넣는다
guide    0건 ( 0.0%)  고친 문장은 있고 치환은 못 한다
bare   104건 (100.0%)  이유만 있고 본보기가 없다
```

규칙별로도 전부 bare 다. topicBreak 36, factListParagraph 27, endingRepeat 17 이 위 셋이고 나머지 열둘도
같다. 즉 이 도구는 실제 글에서 **자리와 이유만 주고 어떻게 쓰는지는 한 번도 보여 주지 않았다.**

`hanlint fix` 가 0% 인 것은 고장이 아니다. 확정 치환이 있는 자리 (번역투, 명령형 뒤 마침표, 이중 부정) 가
이 다섯 편에 없었을 뿐이다. 문제는 나머지 100%에 아무것도 없었다는 것이다.

## 같은 날. 본보기를 넣은 뒤

규칙 52개에 고치기 전과 후의 짝을 데이터로 달았다 (`data/exemplars.toml`). 같은 스냅숏을 다시 재면
지적 104건 전부에 본보기가 붙는다. 나온 규칙 15종 모두 본보기가 있다.

```text
지적 104건
본보기가 붙은 것 104건 (100%)
```

세 자리에 실린다. 사람이 읽는 꼴은 글 끝에 규칙마다 한 줄, `--format json` 은 지적마다 `exemplar`
객체, `hanlint explain` 은 전과 후를 여러 줄로 편다.

## 이 탐침이 다음에 답할 것

여기까지는 **닿았는가**를 잰 것이지 **나아졌는가**를 잰 것이 아니다. 다음 질문은 이것이다.
같은 지적을 받은 AI 가 규칙 이름과 이유만 받을 때와 본보기까지 받을 때 고친 결과가 다른가.
그것은 LLM 호출이 드는 탐침이라 별도 폴더로 만든다.
