# 원문 없는 수사 구조 청사진 탐침

날짜: 2026-08-31

## 물은 것

고정·허가된 한국어 말뭉치 1,600편에서 원문 문장을 생성 재료로 꺼내지 않고 구조 숫자만 주면, 같은
`WritingBrief`를 그대로 준 기준보다 자동 안전 계약을 더 자주 지키는가. 둘 다 안전한 결과가 있으면 전략과
모델을 가린 자연스러움·독자 과업·목소리 평가 패킷을 만들 수 있는가.

## 데이터 경계

`scripts/buildBlueprints.py`는 catalogue의 출처와 라이선스, 고정 manifest, 외부 metadata, 실제 1,600개
원문 해시가 모두 일치할 때만 집계한다. 배포 `blueprints.json`에는 종류별 문서 수, 출처 ID, 말뭉치 파일
해시와 절 수, 절별 문단·문장 수, 문단·문장 글자 수, 인접 문장 길이 차이 및 도입·마무리 위치의
p10·p25·p50·p75·p90만 남긴다. 원문, 제목, URL, 문장과 표현은 없다. 게이트는 값의 문자열을 출처 ID
또는 SHA-256으로 닫고 한글 문자열을 거부한다.

## 설계

- 일곱 프리셋의 기존 사실 고정 `WritingBrief`를 그대로 썼다.
- 기준은 기본 구조화 draft `writingPacket`, 후보는 같은 패킷에 `rhetoricalBlueprintV1`만 opt-in했다.
- 래퍼 프롬프트, 모델과 옵션은 같다. 모델은 `qwen3:8b`, `temperature=0`, `seed=42`,
  `num_predict=1200`, `think=false`다.
- 모델 결과는 고치지 않았다. 각 쌍을 `WritingTrial`로 잠그고 `prepareBlind`가 guard 안전성을 먼저 가렸다.
- 둘 다 자동 계약을 통과한 쌍만 사람 평가용 좌우 비교를 내도록 했다. LLM 평가와 자동 자연스러움 점수는
  만들지 않았다.

예비 실행에서는 보고문·수필·소설 원문의 마크다운 절 중앙값이 하나라 청사진도 `whole`만 냈다. 물리적
절 수와 수사 위치를 같은 것으로 취급한 결함이었다. 절 예산과 도입·본문·마무리의 위치 예산을 분리하고
최종 실행을 새로 만들었다. 아래 수치는 그 최종 판만 센 것이다.

합계는 다음과 같다.

- 전체 자동 계약: 기준 0/7, 후보 0/7
- 사실 표면: 기준 5/7, 후보 6/7
- 길이: 기준 0/7, 후보 1/7
- error 0: 기준 4/7, 후보 4/7
- arena: 후보 안전 승 0, 기준 안전 승 0, 둘 다 안전 0, 둘 다 실패 7
- 사람 평가를 기다리는 블라인드 선호 패킷: 0

구조 예산은 사실 표면과 길이에서 한 과제씩 더 통과했지만 전체 계약을 통과한 결과를 만들지 못했다.
두 결과가 모두 안전한 쌍이 없으므로 자연스러움, 독자 과업과 목소리는 비교할 수 없다. 이 작은 차이를
향상이나 일반 우위로 부르지 않는다. `rhetoricalBlueprintV1`은 기본 패킷에 넣지 않고 opt-in 실험으로 둔다.
