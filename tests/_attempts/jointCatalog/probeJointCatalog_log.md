# jointCatalog 실측 기록

말뭉치가 만든 닫힌 고침 목록이 채워지는지, 그 목록에서 고른 고침이 모델의 자유 고침보다 나은지.

## 왜 이 실험인가

`usageLift` 는 같은 재료 (용례) 를 프롬프트에 얹는 방식을 네 번 쟀고 네 번 다 효과가 없었다 (300쌍, 두 모델, 세 조건,
부호검정 p 1.0000). 그 실험이 남긴 관찰 셋이 이 실험의 설계다.

1. 모델이 새로 만든 어절 결합의 73%가 그 종류의 말뭉치에 없었다. **결합을 지어낸다.**
2. 명사 쌓기를 풀다 `의` 사슬을 만들어 새 error 가 2건에서 10건이 됐다. **고치다 딴 데를 깬다.**
3. 강한 모델은 300/300 을 전부 고쳤다. 원문 유지가 0 이다. **기권하지 않는다.**

셋 다 "무엇을 쓸지" 를 모델에게 물어서 생긴다. 통로를 바꾼다. 말뭉치가 그 자리에 실제로 쓴 것만 모아 닫힌 목록을
만들고, 목록에 넣기 전에 hanlint 로 다시 검사해 규칙이 풀리고 다른 규칙이 늘지 않는 꼴만 남긴다. 모델은 짓지 않고
고른다. 1 은 목록이 말뭉치에서 나오므로, 2 는 거르기가 막으므로, 3 은 `원문 유지` 가 목록의 한 항목이므로 사라진다.

## 사전 등록 (2026-09-20, 돌리기 전에 적는다)

**갈래 셋.** 같은 문장, 같은 지적.

| 갈래 | 누가 | 무엇을 |
|---|---|---|
| `free` | 모델 | 문장을 다시 쓴다. 후보를 보지 않는다 (usageLift 의 reasonOnly 와 같은 프롬프트) |
| `pick` | 모델 | 후보 번호 하나를 고른다. `0` 은 원문 유지 |
| `top` | 아무도 | 목록의 첫 후보. 모델 없는 결정적 기준선 |

**과제.** 사업보고서 300편의 `nounPile` 과 `euiChain` 지적 가운데 (a) 거른 뒤 후보가 하나 이상 남고 (b) 문장이 200자
이하인 것. 규칙마다 75건, 모두 150건. 씨앗 42 로 섞어 고른다. (b) 는 심판이 한 화면에서 넷을 읽게 하려는 제한이고
선택 기준으로 미리 적는다.

**재는 것 넷.**
1. 규칙 해결: 출력이 겨눈 규칙을 푸는가.
2. 새 지적: 다른 규칙이 느는가.
3. 뜻 보존: 원문 명사 핵 가운데 출력에 남은 비율.
4. 블라인드 선호: fresh-context 심판이 원문과 고침 셋을 보고 가장 나은 하나를 고른다. 갈래 이름을 숨기고 과제마다
   씨앗으로 차례를 섞는다. `차이 없음` 을 고를 수 있다.

**판정 조건.**
- **폐기.** `top` 과 `pick` 이 **둘 다** `free` 에 블라인드 선호로 지고 (부호검정 p < 0.01, 승률 차 -10%p 이하) 면 이
  방향을 버린다. 코드와 문서를 지운다.
- **채택.** 계약 조건 (`pick` 과 `top` 의 규칙 해결 100%, 새 지적 0) 을 지키면서 블라인드 선호에서 `free` 에 지지
  않으면 남긴다. 여기서 "지지 않음" 은 위 폐기 조건에 걸리지 않는 것이다.
- 계약 조건이 깨지면 그것은 실험 결과가 아니라 **구현 결함**이다. 고치고 다시 잰다.

**미리 적는 한계.** 이 실험은 후보가 있는 자리만 본다. 후보가 없는 지적에서는 `pick` 과 `top` 이 할 일이 없다.
제품에서의 값은 `채움률 x 여기서의 향상` 이다. 채움률은 `census` 가 따로 소유하며 이 실험의 수와 섞지 않는다.

**지표를 바꾼 이유.** usageLift 의 주 지표 `genreHit` (새 결합이 말뭉치에 있는가) 는 여기서 쓰지 않는다. 후보가
말뭉치에서 나오므로 `pick` 과 `top` 이 구조상 만점이다. 자기 설계로 자기를 칭찬하는 지표는 아무것도 재지 않는다.

## census 결과 (2026-09-20). 채움률

대상 커밋 477fd12 + 이 작업. 사업보고서 300편에서 규칙마다 지적 200건을 씨앗 42 로 골랐다. 근거 색인은 report
(문서 3,193편, 문장 1,056,316개). 후보 생성과 거르기는 제품 코드 (`hanlint.edit.usageCandidates`) 를 그대로 부른다.

```text
                     자리가 나온 지적   규칙을 푸는 후보   다른 규칙을 늘려 쳐냄   채움률
nounPile (200건)      104 (52%)           232개            39개            88/200 (44%)
euiChain (200건)      149 (74%)           225개             3개            98/200 (49%)
```

**읽은 것 셋.**

1. **카탈로그는 비어 있지 않다.** 두 규칙 모두 지적의 절반 가까이에 말뭉치가 뒷받침하는 고침이 하나 이상 남는다.
   방향이 성립하지 않는 경우 (채움률 0 근처) 가 아니다.
2. **거르기가 장식이 아니다.** nounPile 에서 규칙을 푸는 후보 232개 가운데 **39개 (17%) 가 다른 규칙을 늘렸다.**
   대부분 `의` 를 끼워 넣어 euiChain 을 만드는 꼴이다. usageLift 에서 모델이 자유롭게 고치다 새 error 를 2건에서
   10건으로 늘린 바로 그 실패이고, 여기서는 목록에 들어가기 전에 걸린다. euiChain 쪽은 3개뿐인데, `의` 를 빼거나
   바꾸는 고침은 새 결함을 만들 통로가 좁아서다.
3. **나머지 절반은 못 고친다.** 자리가 아예 안 나오는 지적이 nounPile 48%, euiChain 26% 다. 한 회사의 고유한
   명사 쌓기라 말뭉치에 그 결합 자체가 없다. 이 자리는 사람이나 LLM 이 문장을 다시 써야 하고, 이 기능이 닿지 않는다.

제품 가치는 `채움률 x 고침의 질` 이다. 채움률은 여기까지이고, 질은 아래 실험이 잰다.
